# 性能基线存档（2026-10-12）

> 本文档是 bridge/serve 请求路径性能优化的**前后对比基线**。后续性能工作以此为参照：
> 跑 `cargo bench --bench bridge` 与本表对比（criterion 的 `change:` 段给出与上次运行的 Δ%）。
> 机器可读快照（中位数 ns，供 diff）：`docs/perf/data/<日期>.txt`，由
> `scripts/perf-baseline.sh --save` 导出——本次 AFTER 态存档为 `docs/perf/data/2026-10-12.txt`
> （锚定 fe8f317）。criterion 报告本身在 `target/criterion/`，会被下次跑滚动覆盖，不作存档。
> 机器：aarch64-apple-darwin（M 系列，macOS）；cargo bench release profile。

## 方法

- 口径 1（主）：`benches/bridge.rs` criterion 基准，median。新增两个仪器基准补盲区：
  - `js/run_module`：HTTP 真实路径（side-module driver + api 模块 V8 缓存命中）——此前基准只测 `run_with` 纯 script 路径，run_module 的 driver 装载开销是盲区；
  - `js/http.access`：handler 高频的 `http.*` 属性访问 ×100。
- 口径 2（未跑，见「未做项」）：`ab` 端到端 RPS 探针。serve 层修复是结构性去重复功（每请求分配/syscall 计数下降），无单点微基准。

serve 层（结构性，无微基准数字）：每请求少 ~30-40 次头字符串化分配（开 auth 时）；重复静态资产请求从「2 stat + 全量读体 + 200」变「命中 304 零传输」；HTML meta 命中缓存后免每请求读盘 + parse；无注入页面免整份文档拷贝；POST/PUT blob 快速路径免 2 次堆分配。

## 未做项（记录理由）

- **F4 read_capture 零拷贝 / F13 响应头预解析 / F14 body memcpy**：典型场景收益 <1µs 或 <2%，重构面不成比例；大响应/大头部部署有需要时再做。
- **e2e ab 探针**：BEFORE 口径需要旧二进制全量重建，成本超收益；criterion 已隔离各项收益。
- **ldap typed 通道慢于 generic 2.8×**（1.23µs vs 447ns/op）：独立调查项，非请求热路径。
- **跨 isolate 共享 reqwest client**：高 outbound-fetch 部署才值得（连接池/TLS 会话复用跨 16+ isolate）。
- **row_to_json 流式序列化**：消除列名键分配需换输出管线，收益配不上改动面。
