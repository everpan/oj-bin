# db / DB(name) —— 数据库访问

> 本文档由 src/bridge/ 梳理生成；权威 API 参考见 ../devkit/api-manual.md。

## 是什么

为 JS/TS handler 提供关系型数据库访问的全局对象。`db` 即默认库实例（`db === DB("default")`，
引用相等由 bootstrap.js 侧的实例缓存保证），`DB("name")` 取命名库实现多库混用。

- **方言按 DSN 前缀判定**：`mysql://` → MySQL，`postgres://` / `postgresql://` →
  PostgreSQL，其余（含 `sqlite://` / `sqlite::memory:`）→ SQLite；非法 DSN 装配期
  fail-fast。
- **两条访问路径**：安全查询构造器 `db.table(...)`（标识符全部来自 SchemaRegistry
  白名单，值一律绑定参数）与裸 SQL `db.query` / `db.exec`（见下「红线」）。
- **大整数契约**：DB 读出的 64 位整数按值域分流——`|v| ≤ 2^53-1` 给 `number`，
  超出给**十进制字符串**；精确回写用 `toBigInt()` / `toUBigInt()`（见「数值边界
  helpers」与 `../numeric-limits.md`）。
- 插件后端：`oj-db-mysql` / `oj-db-postgres` 作为 cdylib 插件提供真库访问；
  未装插件时 `sqlite://` 由核心内置 `SqlxAccessor` 直出。

## 配置

```yaml
# config.yaml —— db: name → DSN 的 map，键即库名（sqlite/mysql/postgres 可混用）
db:
  default: "sqlite://db.sqlite"
  test: "sqlite://db_test.sqlite"
  analytics: "ENC[...]"   # 明文形态：mysql://user:pass@127.0.0.1:3306/app
  warehouse: "ENC[...]"   # 明文形态：postgres://127.0.0.1:5432/app

# 构造器 LIMIT 策略（仅顶层查询；装配期校验，0 / 倒置 / 超硬顶均启动报错）
db_query:
  default_limit: 100      # 顶层 select 未显式 .limit() 时的隐式上限（默认 100）
  max_limit: 1000         # 显式 .limit(n) 的 clamp 上限（默认 1000；硬顶 100000）

# SQL 执行追踪（dev 默认开 / release 默认关；参数永远脱敏）
db_trace:
  enabled: true           # 缺省 = dev 自动开 / release 自动关；可强制
  redact_params: true     # 默认 true：画像/信封只记参数个数；false 仅让 dev 日志记原值
  slow_ms: 0              # 慢查询阈值(ms)；0 = 全收
  to_log: true            # 是否写 dev 日志（target="oj::sql"）
```

- 凭据一律写 `ENC[...]` 密封值（`oj secret seal` 生成）。
- `oj serve --db <name>` 指定哪个命名库作为默认源（迁移/seed/fixtures 一并跟随）；
  未声明的库名 fail-fast。
- seed.sql 重放仅在默认库为 sqlite 时发生。
- 顶层 select 结果行数 ≥ 生效上限时，响应带 `X-OJ-Row-Limit: <上限>` 头提示可能被截断。

## API

### 实例方法（`db` 与 `DB(name)` 同签名）

| API | 签名 | 说明 |
|---|---|---|
| `DB(name)` | `(name: string) => DBInstance \| undefined` | 取命名库实例；**未配置返回 `undefined`**（不抛错）。`db === DB("default")` |
| `db.table` | `table(name: string) => QueryBuilder` | 安全查询构造器（标识符白名单 + 参数化值），**首选路径** |
| `db.query` | `query(sql: string, params?: unknown[]) => Promise<Row[]>` | 裸 SQL 参数化查询（红线见下；params 可选） |
| `db.exec` | `exec(sql: string, params?: unknown[]) => Promise<number>` | 裸 SQL 参数化执行 → 受影响行数 |
| `db.tx` | `tx(fn: (tx) => unknown) => Promise<unknown>` | 事务（见「事务 db.tx」） |
| `db.stream` | `stream(sql, params?, opts?) => Promise<void> \| AsyncIterable<Row>` | 流式查询（v0.1.37）：`opts.onRow(row)` 回调形态（推荐）或不传 `onRow` 返回 `for await` 异步迭代器；`opts.signal` 接 AbortSignal 取消。**仅非事务目标** |
| `db.nextSeq` | `nextSeq(name: string) => Promise<number \| string>` | 平台序列分配（v0.1.24）：单语句原子取号，替代 `max(id)+1` 竞态；平台表 `_oj_sequences` 首次使用自动建；库级、跨租户共享；值不随事务回滚回退 |
| `db.sqlProfile` | `sqlProfile() => { count, totalMs, slow, byDb, events }` | 本请求 SQL 执行画像（v0.1.51，dev 默认开）；追踪关闭时返回空对象 `{}`；params 永远只记个数 |
| `db.fromJSON` | `fromJSON(snap) => QueryBuilder` | 从 `toJSON()` 快照复原构造器继续链；快照的 `db` 字段只是创建时可见名，复原后绑定**复原方**的库 |
| `db.asSystem` | `asSystem() => DBInstance` | 本请求绕过租户防护（请求级 + 审计日志）；仅系统任务，业务 handler 禁用 |
| `db.asTenant` | `asTenant(id: string) => DBInstance` | 匿名请求声明租户身份（v0.1.20）——租户条件**仍强制**，只是 `tenant_id` 由 `id` 填充；需 `tenant.allow_as_tenant: true` 且请求匿名 |
| `db.leaf / and / or / not` | 条件对象工厂 | 产出不可变条件对象（`db.leaf(field, op, value)` 等）；`where` / `having` 同时接受条件对象或普通 JSON 树 |

条件对象方法：`.tree()` 取纯 JSON 树；`.fields()` 取去重字段名列表；`.has(f)` 判断是否
涉及某字段；`.and(x)` / `.or(x)` / `.not()` 返回**新**对象（不改原对象）。

### 查询构造器（`db.table(name)`）

| 方法 | 说明 |
|---|---|
| `.select(cols)` | 列清单：列名（可 `"t.col"` 限定）、聚合 `{fn, field?, as?}`（`count/sum/avg/min/max`）、case 列 `{case:{when,else?}, as}`、窗口列 `{window:{fn,partition_by?,order_by?}, as}`（`row_number/rank/dense_rank`） |
| `.where(cond)` | 追加条件（多次调用之间 AND）；叶子 `{field, op, value?}` 或嵌套树 `{and/or/not}` / `{exists}`；叶子可带 `subquery` |
| `.orderBy(items)` | `[{field, dir?: "asc"\|"desc"}]`；排序列另有可排序白名单 |
| `.limit(n)` / `.offset(n)` | 分页；limit 被 `db_query.max_limit` clamp，未给取 `default_limit` |
| `.join(table, on, kind?)` | 联表；`on` 只支持列对列等值 `[{left, right}]`（非空）；`kind` 省略为 `inner`，可选 `left`；无表别名 → **自 join 不支持** |
| `.distinct()` | 去重（仅 select） |
| `.groupBy(cols)` / `.having(cond)` | 分组 / 聚合过滤；having 未命中白名单列时按 select 聚合别名展开 |
| `.union(other, kind?)` | 联合查询；`kind` 缺省 `distinct`，可选 `"all"`；成员须显式列且禁 order_by/limit/offset |
| `.with(name, columns, query)` | 非递归 CTE（仅顶层）；`columns` 必填非空，声明的输出列即后续解析的白名单 |
| `.insert(rowOrRows)` | 插入（单行对象或多行数组，多行键集须一致）→ 以 `.run()` 终执行 |
| `.returning(cols)` | insert 返回列（白名单）：`.run()` 改返回行数组 `[{id: n}]`。pg/sqlite 单语句 `RETURNING`；mysql 无 RETURNING，取 `LAST_INSERT_ID()`（**并发下请放进 `db.tx`**，且只接受单列） |
| `.update(sets)` | 更新 → `.run()`；**必须带 where** |
| `.delete()` | 删除 → `.run()`；**必须带 where** |
| `.all()` | select 终执行 → `Promise<Row[]>` |
| `.run()` | DML 终执行 → 受影响行数（带 `returning` 时返回行数组） |
| `.toSQL()` | → `{ sql, params }`（占位符按方言；不执行；大整数参数是 `{"$oj$i64":…}` marker，可直接回放进 `db.query`） |
| `.toJSON()` | → 纯 JSON 快照（可改字段后 `db.fromJSON(snap)` 复原） |

### where 操作符

| op | 含义 | 值要求 |
|---|---|---|
| `eq` / `ne` | 等 / 不等 | 任意（缺省按 null） |
| `gt` / `gte` / `lt` / `lte` | 比较 | 必填（缺 → `gt needs value` 等）；接受 `subquery` 渲染标量子查询 |
| `in` | 集合 | **数组**（缺 → `in needs array value`）；`subquery` 渲染 `IN (SELECT …)` |
| `like` | 模式匹配 | 必填；不接受子查询 |
| `isnull` | IS NULL | 无值；不接受子查询 |

- `value` 与 `subquery` 互斥（`value and subquery are mutually exclusive`）。
- 条件树深度上限 8、叶子数上限 64；嵌套 select 层数上限 4。
- 未知表/列报错（`unknown table '…' in <site>` / `unknown column '…' in <site>`）——标识符
  白名单是注入防线的本体。

### 红线：`db.query` / `db.exec` 的存在与使用边界

`db.query(sql, params?)` / `db.exec(sql, params?)` 提供裸 SQL 通道，**仅在构造器不支持时
使用**（窗口函数 frame、递归 CTE、方言专有语法等）。规则：

1. **动态标识符（表名/列名）只来自 SchemaRegistry**，绝不可拼 JS 字符串；值**只**经
   `params` 绑定参数传入。占位符按方言书写（sqlite/mysql 用 `?`，pg 用 `$1…`）。
2. 裸 SQL 仍过守卫：表归属（ownership_guard）与多租户 `check_tenant_raw`（best-effort
   文本检查：Deny 模式下漏 `tenant_id` 条件 → 拒；参数不含当前租户值 → 拒）。
3. 业务代码默认用 `db.table(...)` 构造器——它把「标识符白名单 + 参数化值 + 租户注入」
   收敛为平台行为，注入面为零。

### 事务 `db.tx`

```ts
await db.tx(async (tx) => {
  // tx 与 db 的 query / exec / table / fromJSON / nextSeq / sqlProfile / 条件工厂同签名
  await tx.table("account").update({ balance: 950 }).where({ field: "id", op: "eq", value: 1 }).run();
});
```

- 回调正常返回 → **提交**；throw / reject → **回滚**并把原错误抛给 handler（rollback 自身
  失败不掩盖业务错误）。
- `tx.table(...)` / `tx.query(...)` 自动走事务同一连接（`tx.table(...).all()` 可读未提交）。
- **嵌套事务被拒**：每请求至多一个活跃事务（`transaction already active (nested tx not
  supported)`）；事务未完结时访问其它库报错（`transaction active on db '…'`），先结当前事务。
- handler 忘记 await 或中途崩溃：请求结束时未完结事务**自动回滚**（服务端 warn 日志）。
- 多租户防护在事务内同样生效（注入发生在路由之前，与走池/走会话正交）。
- `db.stream` 不能在事务内用（`db.stream within an active transaction is not supported`）。

### 数值边界 helpers（全局函数）

JS 的 `number` 是 f64（安全整数上界 `2^53-1`），64 位整数需显式转换（fail-loud，绝不静默
取近似）。完整契约与排障见 `../numeric-limits.md`。

| 函数 | 签名 | 说明 |
|---|---|---|
| `toBigInt` | `(v: string \| number \| bigint) => bigint` | 精确 64 位**有符号**整数 `[-2^63, 2^63-1]`。已坍缩的 number（`Number("<大整数串>")`）、非规范十进制串（`"007"`/`"+1"`/`" 1"`）、超 i64 一律 throw |
| `toUBigInt` | `(v: string \| number \| bigint) => bigint` | 无符号 `[0, 2^64-1]`（v0.1.24）。**只有 MySQL `BIGINT UNSIGNED` 能承载**；PG/SQLite 传它会明确报错（它们的 bigint 就是 i64），请存 text |
| `toDouble` | `(v: string \| number \| bigint) => number` | 显式接受 f64 语义（可能丢精度）。字符串按 `Number()` 语义解析；无 `toFloat`（JS 无 f32 语义） |

- **回写规则**：字符串是文本意图，BigInt 是整数意图——回传字符串写 PG bigint 列必然报错
  （`column "x" is of type bigint but expression is of type text`）；MySQL/SQLite 会隐式转换，
  但不要依赖方言差异。
- 跨 op 编码为 `{"$oj$i64":"<十进制>"}` / `{"$oj$u64":"<十进制>"}`；**`$oj$` 前缀是平台
  保留键**，业务 JSON 数据不得以这类键为唯一键。
- `json.*` / `log` / `mail` 容忍 bigint（自动出十进制字符串）；`es` / `bus` / `mq` /
  `jwt` / `ws.sess.state` **不容忍**——跨这些边界先 `String(v)`。
- MySQL 读侧边界：可读 = 整数家族（含 `BIGINT UNSIGNED`）/ 文本家族 / 二进制 /
  `FLOAT`/`DOUBLE`；`DECIMAL`、日期时间家族、`JSON`、`BIT` 等**一律报错**（点名列名，
  不静默变 null），需要时 `cast(amount as char)` 显式转换。`TINYINT(1)`/`BOOLEAN` 读出
  是 number `1`/`0`。

## 错误

| 场景 | 消息（关键词） |
|---|---|
| `DB(name)` 未配置 | JS 侧返回 `undefined`；op 层报 `db: instance '<name>' not configured` |
| 构造器未知列/表 | `unknown column '<col>' in <site>` / `unknown table '<t>' in <site>` |
| 别名形状违例 | `illegal alias '<a>'`（形状 `^[A-Za-z_][A-Za-z0-9_]*$`） |
| update/delete 无 where | JS 链层 `<verb> requires where`；op 侧 `…requires where (leaf count >= 1)` |
| insert 无行 | `insert needs at least one row` |
| 动词×字段矩阵违例 | `<verb> does not accept <field>`（如 `insert does not accept where`、`select does not accept values`） |
| 操作符缺值 | `gt needs value` / `in needs array value` / `like needs value` |
| 条件树超限 | `condition tree too deep (max 8)` / `condition tree too large (max 64 leaves)` / `empty condition group` |
| value 与 subquery 同给 | `value and subquery are mutually exclusive` |
| 嵌套 select 超限 | `<site>: nested select too deep` / `…must be select` / `…does not accept with/unions (v1)` |
| union/CTE 违例 | `union requires explicit columns` / `union member does not accept order_by/limit/offset` / `cte needs non-empty columns` |
| 嵌套/跨库事务 | `transaction already active (nested tx not supported)` / `transaction active on db '<a>' (finish it before touching db '<b>')` / `no active transaction` |
| 事务内 db.stream | `db.stream within an active transaction is not supported (streaming queries run on the connection pool only)` |
| 序列名非法 | `db.nextSeq: name must be 1..=128 characters` |
| `db.asTenant` 门禁 | `db.asTenant: id must not be empty` / `db.asTenant is disabled: set tenant.allow_as_tenant=true…` / `db.asTenant is only allowed on anonymous requests…` |
| 租户守卫（Deny） | `lacks tenant_id` / `require tenant context` / `must include current tenant id` / `tenant guard: insert tenant_id mismatch…` / `tenant guard: update sets.tenant_id not allowed…` |
| 表归属守卫（deny） | `ownership: 表 "<t>" 属于模块 "<m>"，模块 "<x>" 未声明依赖` |
| bigint 参数超界 | RangeError `db param: bigint … is out of 64-bit range (i64/u64)` |
| 二进制参数 | TypeError `db param: binary values are not supported (use blob.put)` |
| `toBigInt` 已坍缩 number | TypeError `toBigInt: … is not a safe integer (\|v\| > 2^53-1)…` |
| `toBigInt`/`toUBigInt` 非规范串 / 超界 | TypeError `…expected a canonical decimal integer string…` / RangeError `…is out of i64 range` / `…is out of u64 range` |

## 限制

- `db` 配置段是 `name → DSN` 的扁平 map，**没有** per-profile 连接池等子字段（`db_query` /
  `db_trace` 是独立顶层段，不能塞进 `db:`）。
- 构造器无 `first`/`one` 便捷方法——`.limit(1).all()` 后取 `[0]`。
- `.all()` 仅 select；DML 一律 `.run()`。
- join 只支持 inner/left，`on` 只支持列对列等值；自 join 不支持（无表别名）。
- union 不做 intersect/except；窗口函数不做 frame；CTE 非递归且仅顶层。
- `db.stream` 仅非事务目标；第三方插件未实现流式槽时宿主**回落 `db.query` 全量**
  （行为一致，只失去流式内存优势）。
- `db.nextSeq` 的序列**库级、跨租户共享**，需隔离就把租户拼进 name；值只增不复用，
  不随调用方事务回滚而回退；`memory://` 不支持。
- 受影响行数 / `kv.incr` 等走 f64 的通道超 `2^53` 会丢精度（DB 读侧有护栏，这些没有）。
- `db.asSystem()` 每次调用记审计日志（stderr warn），业务 handler 不得使用。

## 案例

### CRUD 接口（全构造器）

```ts
// src/user/api.ts —— 账号表 CRUD（表/列均须已在 SchemaRegistry 登记）
async function get() {
  const id = http.param("id");
  if (id !== undefined) {
    const rows = await db.table("account").select(["id", "name", "role"])
      .where({ field: "id", op: "eq", value: Number(id) }).all();
    if (!rows.length) { json.fail(404, "not found"); return; }
    json.ok(rows[0]);
    return;
  }
  const rows = await db.table("account").select(["id", "name", "role"])
    .orderBy([{ field: "id", dir: "desc" }]).all();   // 隐式 limit = db_query.default_limit
  json.ok(rows);
}

async function post() {
  const b = http.body as { name?: string; role?: string };
  if (!b.name) { json.fail(400, "name required"); return; }
  // returning 取回主键：pg/sqlite 单语句；mysql 并发下请放 db.tx
  const rows = await db.table("account")
    .insert({ name: b.name, role: b.role ?? "user" })
    .returning(["id"]).run();
  json.ok({ id: rows[0].id });
}

async function put() {
  const b = http.body as { id?: number; name?: string; role?: string };
  if (!b.id) { json.fail(400, "id required"); return; }
  const sets: Record<string, unknown> = {};
  if (b.name !== undefined) sets.name = b.name;
  if (b.role !== undefined) sets.role = b.role;
  if (!Object.keys(sets).length) { json.fail(400, "nothing to update"); return; }
  const n = await db.table("account").update(sets)
    .where({ field: "id", op: "eq", value: b.id }).run();
  json.ok({ affected: n });
}

async function del() {
  const id = Number(http.param("id", 0));
  const n = await db.table("account").delete()
    .where({ field: "id", op: "eq", value: id }).run();
  json.ok({ affected: n });
}
export default { get, post, put, del };
```

```bash
curl -X POST http://localhost:9778/v1/api/user/ \
  -H 'content-type: application/json' -d '{"name":"neo"}'
# → {"code":0,"msg":"ok","data":{"id":7}}
curl 'http://localhost:9778/v1/api/user/?id=7'
```

### 条件查询分页（条件树 + limit/offset）

```ts
// src/order/list/api.ts —— 关键字/金额区间/状态过滤 + 分页
async function get() {
  const kw = http.param("kw");                 // 可空
  const status = http.param("status");
  const min = Number(http.param("min", 0));
  const page = Math.max(1, Number(http.param("page", 1)));
  const size = Math.min(100, Number(http.param("size", 20)));

  const cond = db.and(
    db.leaf("amount", "gte", min),
    ...(kw ? [db.leaf("no", "like", `%${kw}%`)] : []),
    ...(status ? [db.leaf("status", "eq", status)] : []),
  );
  const rows = await db.table("orders")
    .select(["id", "no", "amount", "status"])
    .where(cond)
    .orderBy([{ field: "id", dir: "desc" }])
    .limit(size).offset((page - 1) * size)
    .all();
  const total = await db.table("orders").select([{ fn: "count", as: "c" }]).where(cond).all();
  json.ok({ rows, total: total[0].c, page, size });
}
export default { get };
```

```bash
curl 'http://localhost:9778/v1/api/order/list/?kw=A&min=100&page=2&size=20'
# 显式 limit 超过 db_query.max_limit 会被 clamp；结果行数 ≥ 生效上限时
# 响应带 X-OJ-Row-Limit 头提示可能被截断
```

### 事务转账（db.tx 同连接）

```ts
// src/pay/transfer/api.ts —— 构造器 sets 只接受常量 → 先读余额再写
async function post() {
  const b = http.body as { from?: number; to?: number; amount?: number };
  if (!b.from || !b.to || !b.amount || b.amount <= 0) {
    json.fail(400, "from/to/amount required"); return;
  }
  try {
    await db.tx(async (tx) => {
      const from = await tx.table("account").select(["id", "balance"])
        .where({ field: "id", op: "eq", value: b.from }).all();
      const to = await tx.table("account").select(["id", "balance"])
        .where({ field: "id", op: "eq", value: b.to }).all();
      if (!from.length || !to.length) throw new Error("account not found");
      if (Number(from[0].balance) < b.amount) throw new Error("insufficient balance");
      await tx.table("account").update({ balance: Number(from[0].balance) - b.amount })
        .where({ field: "id", op: "eq", value: b.from }).run();
      await tx.table("account").update({ balance: Number(to[0].balance) + b.amount })
        .where({ field: "id", op: "eq", value: b.to }).run();
      // throw 即整体回滚；正常返回即提交
    });
    json.ok({ ok: true });
  } catch (e) {
    json.fail(409, String(e));
  }
}
export default { post };
```
