# Kafka / RabbitMQ —— 命名 MQ 客户端与持久消费

> 本文档由 src/bridge/ 梳理生成；权威 API 参考见 ../devkit/api-manual.md。

## 是什么

`Kafka(name)` / `RabbitMQ(name)` 全局工厂（`src/bridge/mq.rs` + `bootstrap.js`
`__ojMq`/`mqClient`）提供**命名 MQ 客户端**：`kafkas:` / `rabbits:` 配置段的每个键装配
为一个实例（值 JSON 原样透传给 `oj-bus-kafka` / `oj-bus-rabbitmq` 插件的 **mq 轴**），
JS 按名取用。同名实例进程内是**同一对象**（JS 缓存保证同一性）；未配置的名字返回
`undefined`（不是抛错），调用前先判空。

与 `bus` 的分工（bus vs mq 选择）：

| | `bus`（bus 轴） | `Kafka`/`RabbitMQ`（mq 轴） |
|---|---|---|
| 语义 | 广播扇出给在线 WS 客户端 | 持久队列逐条消费 |
| 可靠性 | fire-and-forget，无订阅即丢 | 消费组 offset / 手动 ack，at-least-once |
| 配置段 | `broker:` | `kafkas:` / `rabbits:` |
| 消费上下文 | WS 连接订阅 | **仅长任务**（`src/tasks/`） |
| 典型场景 | 聊天室、实时推送 | 订单事件、异步任务队列、对账 |

同一套 Kafka 可以同时配 `broker:`（分布式 bus 扇出）与 `kafkas:`（持久消费），
两段各司其职、互不干扰。

## 配置

```yaml
kafkas:            # 命名 Kafka 实例：每个键 = 一个 Kafka("<名>")
  default:         #   值 JSON 透传 oj-bus-kafka 插件（mq_connect）
    brokers: ["127.0.0.1:9092"]
    group: "sample"          # 消费组
  # analytics: { brokers: [...], group: "g2" }   # 多实例：Kafka("analytics")

rabbits:           # 命名 RabbitMQ 实例：RabbitMQ("<名>")
  default:
    url: "amqp://guest:guest@127.0.0.1:5672"

tasks:             # 消费面仅在长任务上下文可用
  dir: "tasks"             # src/tasks/ 下 task_{name}.ts / {name}_task.ts
  stop_grace_secs: 30      # 停机宽限；poll 的 timeoutMs 应显著小于它（如 ≤1s）
```

- `Kafka("default")` 的 `"default"` 经注册表别名解析（CLI `--kafka`/`--rabbit` 选源）。
- 段缺省 = 无实例：`Kafka("x")` 返回 `undefined`。
- 底层连接在装配期建立，插件拒绝/连接失败 → 启动 fail-fast。

## API

客户端公共面（全上下文可用）：

| API | 签名 | 说明 |
|---|---|---|
| `Kafka(name)` / `RabbitMQ(name)` | `(name: string) => instance \| undefined` | 取命名实例；未配置返回 `undefined`；同名恒为同一对象 |
| `kind()` | `() => Promise<"kafka" \| "rabbit">` | 实例类型 |
| `metadata()` | `() => Promise<Json>` | broker 概览（kafka：`{kind:"kafka", topics:[...]}`） |

`Kafka(name)` 生产/消费面：

| API | 签名 | 说明 |
|---|---|---|
| `send` | `(topic: string, o: {value?, key?, partition?, headers?}) => Promise<{sent:1}>` | 发送 record。`value` 为 JSON 值（序列化为载荷）；`value` 传 `Uint8Array`/`ArrayBuffer` → **base64 进 `value_b64`，record 载荷 = 原始字节**（v0.1.16）。`key`/`partition`/`headers` 可选 |
| `poll` | `(topics: string[], o?: {max?, timeoutMs?}) => Promise<{messages}>` | **仅任务上下文**。拉至多 `max` 条（默认 100）或 `timeoutMs`（默认 1000ms）到期先到为准。**实例级单 poller**：第二个并发 poll 报 `instance busy`。**消费会话 topic 固化**：首次 poll 按当时 topics 建订阅，其后换 topics 被忽略 |
| `commit` | `(m: MqMessage) => Promise<{}>` | **仅任务上下文**。显式 TPL 提交 **offset+1**（同步提交，spawn_blocking）——把 poll 返回的消息**原样回传**即可；须先 poll 建立消费会话 |

`RabbitMQ(name)` 生产/消费面：

| API | 签名 | 说明 |
|---|---|---|
| `publish` | `(exchange: string, routingKey: string, value, o?: {headers?}) => Promise<{sent:1}>` | 发送消息（`send` 的 rabbit 命名）。`value` 二进制语义同 Kafka（字节走 `value_b64`） |
| `poll` | `(queues: string[], o?: {max?, timeoutMs?}) => Promise<{messages}>` | **仅任务上下文**。逐队列轮转 `basic_get`（手动 ack 模式，`no_ack:false`；每条一个 round-trip）；`max` 默认 10，`timeoutMs` 默认 1000ms（空队列 25ms 步进等待至预算耗尽） |
| `ack` | `(m: MqMessage) => Promise<{}>` | **仅任务上下文**。确认投递（消息原样回传，按 `delivery_tag` 取 Acker） |
| `nack` | `(m: MqMessage, requeue?: boolean) => Promise<{}>` | **仅任务上下文**。拒绝投递；`requeue: true` 重新入队 |

消息形状 `MqMessage`（poll 返回的元素）：
`{topic, partition?, offset?, key?, value, value_b64?, headers?, ts?, delivery_tag?}`。

- kafka：`topic`/`partition`/`offset` 全填，`delivery_tag` 恒无；rabbit：`topic` = queue 名，
  `delivery_tag` 关联 ack/nack。
- 载荷为 UTF-8 时 `value` 是解析后的 JSON（解析失败为字符串）；**非 UTF-8 载荷** →
  `value` 为 `null`、`value_b64` 为 base64 字符串（v0.1.16 起，自行解码还原字节）。

## 错误

| 场景 | 消息关键词 |
|---|---|
| 未配置的名字 | `Kafka("nope")` / `RabbitMQ("nope")` 返回 `undefined`（**不抛错**，自行判空） |
| HTTP/WS handler 里调 poll/commit/ack/nack | `mq.<method> requires a task context (long-running tasks only; use send/publish from HTTP/WS)` |
| 同名实例第二个并发 poll | `mq: instance busy (another active poller)` |
| kafka 未 poll 先 commit | `kafka commit: no active consumer session (poll first)` |
| rabbit ack/nack 载荷缺/错 delivery tag | `rabbitmq ack/nack: payload requires deliveryTag (poll 返回的消息原样回传)` / `rabbitmq ack/nack: unknown deliveryTag <tag>` |
| broker 侧发送/拉取失败 | `kafka send <topic>: ...` / `kafka poll: ...` / `rabbitmq publish <exchange>/<routingKey>: ...` 等（插件原始错误透出） |

## 限制

- **消费面四方法（poll/commit/ack/nack）仅长任务上下文可用**——HTTP/WS handler 调用直接
  报错。生产面（send/publish/kind/metadata）全上下文可用。
- **实例级单 poller**：一个实例同一时刻只允许一个活跃 poll。
- **kafka 消费会话 topic 固化**：首次 poll 建订阅后换 topics 无效；要换主题就换实例名。
- **rabbit poll 是逐条 `basic_get`**（非批量 prefetch）——高吞吐场景注意 round-trip 成本；
  队列须先存在，否则 basic_get 404。
- **at-least-once，必须幂等消费**：kafka 按 offset+1 提交，崩溃在「处理后、commit 前」
  会重复消费；rabbit 同理（ack 前崩溃 → 重投）。业务处理要幂等（唯一键/去重表）。
- **kafka 多分区主题必须按分区各提交一次**：commit 只推进该消息所在分区——取每个分区
  最大 offset 的消息各提交一次；只提交最后一条会丢其余分区的进度。
- 任务运行时**无 timer 全局**（`setTimeout` 不可用）；等待一律 `await tasks.sleep(ms)`。
- `timeoutMs` 应显著小于 `tasks.stop_grace_secs`（默认 30s），否则停机时任务在一次长
  poll 中错过退出窗口，到点被看门狗强杀（记 Killed）。
- 任务文件是 ES 模块：用顶层 await 必须带 `export {};`；改任务文件需重启进程（无热重载）。

## 案例

### HTTP handler 生产订单事件（kafka send）

```ts
// src/order/create/api.ts —— 生产面无上下文限制，HTTP handler 直接发
const k = Kafka("default");
if (!k) throw new Error("kafka not configured"); // 未配置返回 undefined，先判空

async function post() {
  const { item, qty } = http.body ?? {};
  if (!item || !qty) { json.fail(400, "item/qty required"); return; }
  const id = db.table("orders").insert({ item, qty, status: "new" });
  await k.send("orders", {
    key: String(id),                       // 同 key 落同分区 → 单键有序
    value: { type: "order.created", id, item, qty },
  });
  json.ok({ id });
}
export default { post };
```

```yaml
# config.yaml
kafkas:
  default:
    brokers: ["127.0.0.1:9092"]
    group: "order-worker"
```

```bash
curl -X POST -H 'Content-Type: application/json' -d '{"item":"book","qty":2}' \
  http://localhost:9778/v1/api/order/create/
# → {"code":0,"data":{"id":…}}
```

### 长任务消费 kafka：按分区 commit（顺序语义 poll → 处理 → commit）

```ts
// src/tasks/task_order_worker.ts —— TLA 长任务（顶层 await 循环）
export {};
const k = Kafka("default");
while (!tasks.stopping()) {
  const { messages } = await k.poll(["orders"], { max: 100, timeoutMs: 1000 });
  // commit(offset+1) 只推进该消息所在分区——多分区主题按分区各提交一次，
  // 只提交最后一条会丢其余分区的进度。处理须幂等（at-least-once）。
  const deepest = new Map(); // partition → 该分区最深的消息
  for (const m of messages) {
    if (m.value?.type === "order.created") {
      db.table("orders").where({ id: m.value.id }).update({ status: "processing" });
    }
    const cur = deepest.get(m.partition);
    if (!cur || m.offset > cur.offset) deepest.set(m.partition, m);
  }
  for (const m of deepest.values()) await k.commit(m); // 原样回传即可
}
```

### 长任务消费 RabbitMQ：ack / nack(requeue)

```ts
// src/tasks/task_mail_worker.ts
export {};
const r = RabbitMQ("default");
while (!tasks.stopping()) {
  const { messages } = await r.poll(["mail.send"], { max: 10, timeoutMs: 1000 });
  for (const m of messages) {
    try {
      await mail.send({ to: m.value.to, subject: m.value.subject, text: m.value.text });
      await r.ack(m);          // 处理成功：确认（消息原样回传）
    } catch (e) {
      log.error("mail task", { err: String(e) });
      await r.nack(m, true);   // 失败：requeue 重投（注意死循环风险，生产配死信队列）
    }
  }
}
```

```yaml
# config.yaml
rabbits:
  default:
    url: "amqp://guest:guest@127.0.0.1:5672"
```

```ts
}

```
