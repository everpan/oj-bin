# kv / redis —— KV 存储

> 本文档由 src/bridge/ 梳理生成；权威 API 参考见 ../devkit/api-manual.md。

## 是什么

为 JS/TS handler 提供 Redis 风格键值存储的全局对象。`kv` 与 `redis` 两个全局**同源同面**
（bootstrap.js 426~444：逐方法绑定同一组 op），`redis` 是遗留别名，新代码用 `kv`。

后端两档：

- **未配置 `redis:` 段** → 进程内存 KV（`InMemoryKV`，惰性过期），零依赖可跑；
- **配置了 `redis:` 段** → 由 `oj-kv-redis` 插件真连 Redis（启动探活，连不上
  **fail-fast**），此时 `kv` / `redis` 全局与 auth 会话共享同一 Redis——这是多实例
  水平扩展的前提（内存 KV 不跨进程共享）。

## 配置

```yaml
# config.yaml —— redis: name → URL 的 map，键即 profile 名（与 db: 同形）
redis:
  default: "ENC[...]"   # 明文形态：redis://:pass@127.0.0.1:6379/0
  # cache: "redis://127.0.0.1:6379/1"
```

- **段缺省 = 内存 KV**（不报错，零配置可开发）；段存在即真连，启动时单次探活，
  连接/认证失败直接退出（不让无限重试把启动挂死）。
- `oj serve --redis <profile>` 指定哪个命名 profile 作为默认源；未声明 fail-fast。
- 凭据一律写 `ENC[...]` 密封值；URL 在日志里脱敏为 `redis://***@host`。
- **没有 `Redis(name)` 命名实例**（bootstrap.js 注明未移植）——多 profile 仅供启动期
  选择默认源，handler 侧始终面对一个 `kv`。

## API

`kv.*` 与 `redis.*` 完全同签名：

| API | 签名 | 说明 |
|---|---|---|
| `kv.get` | `get(key: string) => Promise<string \| null>` | 取值；缺失 / 已过期为 `null` |
| `kv.set` | `set(key: string, value: string) => Promise<boolean>` | 写值（值按 `String(value)` 存）；**覆盖写会清掉既有 TTL** |
| `kv.del` | `del(key: string) => Promise<boolean>` | 删键；幂等（不存在视为成功） |
| `kv.expire` | `expire(key: string, ttlSec: number) => Promise<boolean>` | 设过期（**单位：秒**）；键不存在 → `false`。JS 侧换算为毫秒传 op；真 Redis 走 `EXPIRE`（只认整秒，毫秒向上取整到 ≥1s），内存 KV 惰性过期 |
| `kv.incr` | `incr(key: string) => Promise<number>` | 原子自增并返回新值；键不存在从 0 起（首次返回 1）；现存值非数字 → 抛错 |

## 错误

| 场景 | 消息（关键词） |
|---|---|
| `incr` 命中非数字值 | `kv.incr: <key> is not a number (<value>)` |
| `expire` 对缺失键 | 不报错，返回 `false` |
| 后端不支持 expire/incr（自定义后端未覆写） | `KVStore expire: not supported (<key>)` / `KVStore incr: not supported (<key>)` |
| Redis 连接 / 认证失败 | **启动期 fail-fast**（装配报错退出，非运行时错误） |

## 限制

- 值为**字符串**：`kv.set` 内部 `String(value)`，对象请自行 `JSON.stringify` /
  `JSON.parse`。
- `kv.incr` 返回 f64：计数器超 `2^53` 后会**先丢精度**（与 DB 读侧不同，kv 无护栏）。
  需要精确大计数时改用 DB 或自行以字符串存储。
- TTL 以秒计且只增式语义：内存 KV 的过期是**惰性**的（到点后第一次 `get` 才删）；
  `set` 覆盖写会把 TTL 清掉（永不过期），要保 TTL 需重设 `expire`。
- 内存 KV 只在单进程内有效：多实例部署必须配置真 Redis（auth 会话也依赖这一点）。
- 无 `Redis(name)` 命名实例、无 `mget`/`hset`/`lpush` 等复合结构 API——复杂结构请
  JSON 序列化或走 DB。

## 案例

### 登录会话缓存（set + expire）

```ts
// src/session/login/api.ts
async function post() {
  const b = http.body as { name?: string };
  if (!b.name) { json.fail(400, "name required"); return; }
  const rows = await db.table("account").select(["id", "name"])
    .where({ field: "name", op: "eq", value: b.name }).all();
  if (!rows.length) { json.fail(401, "bad credentials"); return; }
  const sid = crypto.randomHex(32);                        // 64 字符不透明串
  await kv.set(`sess:${sid}`, JSON.stringify({ uid: rows[0].id, name: rows[0].name }));
  await kv.expire(`sess:${sid}`, 3600);                    // 秒
  json.ok({ sid, ttl: 3600 });
}
export default { post };
```

### 发送接口限流（incr + expire 滑动窗口）

```ts
// src/sms/send/api.ts —— incr 键不存在从 0 起、返回新值；首次命中补过期即构成窗口
async function post() {
  const phone = String((http.body as { phone?: string }).phone ?? "");
  if (!phone) { json.fail(400, "phone required"); return; }
  const key = `rl:sms:${phone}`;
  const n = await kv.incr(key);
  if (n === 1) await kv.expire(key, 60);                   // 窗口期 60 秒
  if (n > 5) { json.fail(429, "too many requests"); return; }
  // …调用短信通道…
  json.ok({ sent: true, count: n });
}
export default { post };
```

### 订单详情读穿缓存（get → miss 回源 DB → set）

```ts
// src/order/detail/api.ts
async function get() {
  const id = Number(http.param("id", 0));
  const key = `order:${id}`;
  const hit = await kv.get(key);
  if (hit !== null) { json.ok({ cached: true, data: JSON.parse(hit) }); return; }
  const rows = await db.table("orders").select(["id", "no", "amount"])
    .where({ field: "id", op: "eq", value: id }).all();
  if (!rows.length) { json.fail(404, "not found"); return; }
  await kv.set(key, JSON.stringify(rows[0]));
  await kv.expire(key, 300);                               // 5 分钟
  json.ok({ cached: false, data: rows[0] });
}
export default { get };
```
