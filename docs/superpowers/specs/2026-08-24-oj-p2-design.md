# oj v0.2 能力面设计（OJ-1…OJ-6）

日期：2026-08-24
状态：已实现（OJ-1…OJ-6 全部落地并通过 P7 总审：全量测试双绿 + code review + 手工冒烟）
前置：`2026-08-22-oj-server-sample-design.md`（v0.1 架构与 D1–D4 裁决）、
`2026-08-23-oj-build-design.md`（构建契约）。
本文勾销 v0.1 已知限制中的「db 仅 sqlite」「Redis 退内存」两项，并新增

## 0. 范围与裁决记录

六项一次成文，按子系统分节；每节可独立实现、独立回滚。对话期关键裁决：

| 决策点 | 裁决 |
|---|---|
| OJ-1 目标 | 进程内多库混用（db map 各自 DSN，可 sqlite+mysql+pg 并存） |
| OJ-3 语义 | 仅注入上下文（`http.tenantId`），SQL 过滤归业务，不做自动改写 |
| OJ-4 模型 | 含自签发登录（login/refresh/logout + user_table + session） |
| OJ-4 匿名 | 配置路径列表（`auth.anonymous_paths`） |
| OJ-5 后端 | blob 双驱动：local + S3/MinIO（object_store） |
| OJ-6 范围 | 全做：真 Redis + 订阅发布总线 + ES op |
| 注入机制 | handle() 内前置管线（不引 axum middleware layer） |
| 事件总线 | 订阅发布模型（publish 广播 + WS 会话订阅） |

## 1. OJ-1 多库 DSN

**现状**：`SqlxAccessor::connect` 已按 DSN scheme 分发（`install_default_drivers`，
mysql/pg feature 已编译），限制仅在 `oj/src/server_cmd.rs` 的 `resolve_sqlite()`
（非 `sqlite://` fail-fast）。

**改动**：`resolve_sqlite` → `resolve_dsn(dsn, config_dir)`：

- `sqlite://` 相对路径照旧归一（相对 config 目录）；`sqlite::memory:` 原样；
  缺文件建空库语义不变；单连接（写锁）不变。
- `mysql://`、`postgres://`、`postgresql://` 原样透传，走 sqlx 默认池参数。
- 其余 scheme 启动报错（未知方言 fail-fast）。

**配套**：

- seed.sql 仅重放到 sqlite 库（现状语义）；mysql/pg 建库/迁移归运维，v0.2
  不做方言化 seed（分号切分规则本就 sqlite 专用）。
- 构造器（query.rs）按 accessor 方言选 sea_query QueryBuilder
  （sqlite/mysql/pg 三选）；裸 SQL 占位符方言（`?` vs `$1`）归业务责任，
  由构造器统一处理。
- accessor 记录自身 scheme（从 DSN 前缀判定），供构造器与后续能力取用。

## 2. OJ-2 事务 db.tx

**契约**（沿用 `docs/rust-core-runtime-revised.md` P1 设计）：回调式、Rust 持有
begin/commit/rollback、`Bridge` 请求结束保底回滚、每请求单活跃事务、
原始 SQL 与构造器共用同一事务。

**JS API**：

```js
await db.tx(async (tx) => {
  await tx.exec("update acct set bal = bal - ? where id = ?", [100, 1]);
  await tx.table("tx_log").insert({ acct: 1, amt: 100 });
});  // fn 抛错 → 回滚并原样抛出；正常返回 → commit 后返回 fn 结果
```

- `DB(name).tx(...)` 同形；`tx` 是 db 的镜像（query/exec/table），事务内全部
  走同一连接。
- **实现**：op 三原语 `op_db_tx_begin(name)/op_db_tx_commit(name)/op_db_tx_rollback(name)`；
  活跃事务存 per-request Bridge 状态（Rc 层）；query/exec/table op 先查活跃
  tx 再落 pool。JS wrapper 在 bootstrap.js：begin → fn → commit，catch →
  rollback → rethrow。
- **保底**：请求清理路径（Bridge drop 对应时点）仍有未完结 tx → rollback
  并 warn 日志。
- **单活跃**：已有活跃 tx 再 begin → 报错；savepoint 不做（YAGNI）。

## 3. OJ-3 多租户（仅注入）

- config：`tenant: { enable: bool, header_key: string = "X-TENANT-ID" }`。
- handle() 前置管线（仅 enable 时介入，未配置零开销）：
  - header 缺失或空 → 400 信封 `missing tenant header: <key>`，不进 JS。
  - 命中 → `RequestInfo.tenant_id` → bootstrap `http.tenantId`（惰性 Proxy
    一并暴露，同现有 http 形状）。
- SQL 过滤归业务（`where tenant_id = ?`）；不做自动 SQL 改写（对话裁决）。
- 租户校验（该 id 是否存在/合法）归业务。

## 4. OJ-4 JWT 鉴权 + 自签发登录

### 4.1 内置 auth 路由（Rust 实现，不进 JS）

挂 `{base}/auth/*`，无热重载需求（安全关键路径不随业务代码热更）：

| 路由 | 请求 | 响应 |
|---|---|---|
| POST `/auth/login` | `{username, password}` | `{access_token, refresh_token, expires_in, user:{id,roles}}` |
| POST `/auth/refresh` | `{refresh_token}` | 新 token 对（轮换：旧 refresh 作废） |
| POST `/auth/logout` | Bearer 或 `{refresh_token}` | 删除 session |

- 登录查 `auth.user_table`（默认 `users`），bcrypt 验证 `password_hash` 列。
  最小 schema：`users(id, username UNIQUE, password_hash, roles)`，
  `roles` 存 JSON 数组字符串。
- 签发：jsonwebtoken，`auth.signing_method`（HS256|HS384|HS512），
  access claims `{sub: user_id, roles, iat, exp}`；时长
  `auth.access_token_duration` / `auth.refresh_token_duration`
  （humantime，默认 60s / 30d——refresh 用不透明随机串，非 JWT）。
- session：`{refresh_token_hash → {user_id, exp}}` 存 redis（key 前缀
  `AUTH-SESSION:`，TTL = refresh 时长）；未配 redis 退内存 KV 并 warn
  （多实例不共享，ops 手册注明）。**偏离遗留形状**：不做 DB session 表
  （`session_table_name` 弃用）。
- login/refresh 天然免验（无需配置）；logout 需有效 Bearer 或 refresh_token。

### 4.2 管线（handle() 前置，顺序固定）

1. 路径命中 `{base}/auth/*` → 交内置 auth 路由。
2. 匹配 `auth.anonymous_paths`（业务自定义免验列表，如 `/health`；
   匹配语义：去 base 后的完整路径相等，支持尾部 `/*` 通配一层前缀）→ 放行。
3. 其余：验 `Authorization: Bearer <access>`——缺头/坏签名/过期 → 401 信封。
4. 通过 → `RequestInfo.user {id, roles, claims}` → bootstrap `http.user`。

- 未配置 `auth`（无 jwt_secret）→ 整层不启用，行为与 v0.1 完全一致
  （sample 场景零迁移成本）；jwt_secret 为空串 → 启动报错（防呆）。
- 依赖新增：jsonwebtoken、bcrypt。

## 5. OJ-5 文件上传 + blob 双驱动

### 5.1 multipart（axum 层解析）

- 请求 `Content-Type: multipart/form-data` → handle() 解析（multer）为
  `RequestInfo.files: [{field, filename, content_type, bytes}]` → JS
  `http.files`；multipart 的文本字段以 `{字段名: 值}` 对象作为 `http.body`
  传入。非 multipart 请求 body 语义不变。
- 大小上限 `server.max_upload_bytes`（默认 10 MiB）；超限 413 信封。
- 非 multipart 请求零介入。

### 5.2 blob op（object_store：local/s3 同一 API）

- config：
  `blob: { driver: local|s3, root: "uploads"（local）, endpoint, bucket, region, access_key, secret_key, path_style: bool（MinIO true） }`。
- JS 面：`await blob.put(key, bytes, contentType?) / blob.get(key) → bytes /
  blob.del(key) / blob.url(key)`。
- local：落 `blob.root`（相对 config 目录），key 按现有静态段校验规则防穿越；
  `blob.url` → `{base}/blob/{key}`。
- s3：put/get/del 直连；`blob.url` → SigV4 presign GET（默认 15 分钟）。
- 新增公开下载路由 `{base}/blob/{key}`（GET，local 驱动时；s3 时 302 跳
  presign）。**公开语义**：无鉴权（前端 `<img>`/下载场景）；私有下载需求
  归业务前置反代或直接用 s3 presign。
- 未配置 `blob` → op 报「blob not configured」。

## 6. OJ-6 真 Redis + 订阅发布总线 + ES

### 6.1 真 Redis

- redis crate（tokio），`redis.default` 等 DSN 真连，**启动 fail-fast**
  （连接失败即退，不再静默退内存——session 一致性要求）。
- 未配置任何 redis DSN → 退内存 KV（现状，测试/单机友好）并 warn。
- op 面：现有 get/set/del 升级为真实现（值语义保持字符串），
  新增 `expire(key, ttl)` / `incr(key)`（session TTL 与计数场景）。

### 6.2 bus（订阅发布模型）

- Rust 侧：`tokio::sync::broadcast` 进程内总线（topic → channel）。
- JS 面：
  - `bus.publish(topic, data)`：任意 handler 可发，fire-and-forget，
    无订阅者时丢弃（broadcast 语义）。
  - `bus.subscribe(topic)`：**仅在 WS 会话上下文可用**（handler 内调用，
    注册到当前 ws 连接）；publish 后所有订阅该 topic 的 ws 客户端收到
    JSON 帧 `{topic, data}`。
- 订阅生命周期 = ws 连接生命周期（连接断开自动注销）。
- **明示限制**：HTTP 请求 runtime 随请求销毁，不提供请求内 subscribe
    （架构使然；跨进程广播也不做，多实例需外接 redis pub/sub，留待需要时）。

### 6.3 ES op（薄封装）

- config：`es: { endpoint: "http://es:9200" }`（未配置 → op 报未启用）。
- JS 面：`await es.search(index, dsl)` / `es.index(index, id, doc)` /
  `es.del(index, id)`——内部 reqwest 直调 `_search` / `_index?refresh=true`
  / `_delete`，透传响应 JSON（失败原样抛 HTTP 状态与 body）。

## 7. 配置总形状（sample/config.yaml 目标）

```yaml
server:
  host: "localhost"
  port: 9778
  base: "/v1/api"
  root: "dist"              # 静态站点
  timeout: "30s"
  pool_size: 4
  max_upload_bytes: 10485760
db:
  default: "sqlite://db.sqlite"
  analytics: "mysql://user:pass@127.0.0.1:3306/app"   # 可选，任意名字多库
redis:
  default: "redis://127.0.0.1:6379/1"   # 真连；省略整节 = 内存 KV
tenant:
  enable: true
  header_key: "X-TENANT-ID"
auth:
  jwt_secret: "change-me"
  signing_method: "HS256"
  access_token_duration: "60s"
  refresh_token_duration: "720h"
  anonymous_paths: ["/health"]
  user_table: "users"
blob:
  driver: "local"        # local | s3
  root: "uploads"
  # s3: { endpoint, bucket, region, access_key, secret_key, path_style }
es:
  endpoint: "http://127.0.0.1:9200"
```

新配置节全部可省：不配 `tenant` 不注入；不配 `auth` 整层关闭；不配 `blob`/`es`
对应 op 报未启用。`tenant`/`auth` 的遗留形状按上述收紧（多余键 serde 忽略
或显式报错——实现期定为「未知键忽略」，与现行 config 行为一致）。

## 8. 错误处理汇总

| 场景 | 行为 |
|---|---|
| 未知 DSN scheme | 启动 fail-fast |
| 非库不存在类连接失败（mysql/pg/redis） | 启动 fail-fast |
| tenant 开启且 header 缺失 | 400 信封 |
| 未匿名路径缺/坏/过期 token | 401 信封（`json.fail(401,…)` 同构） |
| login 凭据错误 | 401 信封（不区分用户不存在/密码错） |
| tx 嵌套 begin | 抛 JS Error（500 信封） |
| 请求结束未完结 tx | 自动 rollback + warn 日志 |
| multipart 超限 | 413 信封 |
| blob/es 未配置即调用 | 抛 JS Error（500 信封） |
| bus.publish 无订阅者 | 静默丢弃 |

## 9. 测试策略

- 每子系统 E2E（`oj/tests/e2e.rs` 追加，沿用 E2E_LOCK 串行锁）：
  - 多库：sqlite 双库 + mysql/pg `#[ignore]` 集成测试（有环境才跑）。
  - tx：提交可见 / 回滚不可见 / fn 抛错自动回滚 / 请求超时保底回滚（借
    KillSwitch 路径）/ 嵌套报错。
  - 租户：注入可见、缺头 400、未启用零介入。
  - auth：login→带 token 访问→篡改签名 401→过期 401→refresh 轮换→
    logout→旧 token 401（session 删除）；anonymous_paths 生效。
  - blob：local 全链路（上传→url→GET→del→404）+ 超限 413 + 穿越拒绝；
    s3 `#[ignore]`。
  - redis：内存退路 E2E；真连 `#[ignore]`。
  - bus：两 ws 会话订阅同 topic，HTTP handler publish，双端收帧。
  - es：`#[ignore]`（或本地 mock endpoint 走 e2e 可选）。
- 单测：resolve_dsn 分发、tx 原语状态机、token 签验/过期、anonymous_paths
  匹配、blob key 校验、bus topic 路由。
- 双绿纪律不变：debug 全测 + release build；新增依赖（jsonwebtoken、bcrypt、
  object_store、redis、multer）进各自 crate。

## 10. 明示不做（v0.2 边界）

- 自动租户 SQL 改写；savepoint/嵌套事务；mysql/pg 方言 seed 与迁移工具。
- OAuth providers / on_provider_connect / 外部 auth_url 跳转（遗留键弃用）。
- 跨进程/分布式事件总线（多实例需外接 redis pub/sub，留待需要）。
- blob 分片上传/断点续传；ES 索引生命周期管理。
- SPA 静态回退（维持 v0.1 裁决）。
