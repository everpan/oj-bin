## 1. 问题

`anonymous_paths`（`tenant.` 免租户头 / `auth.` 免 Bearer，均为**去 base 前缀**的路径列表，
四种通配形态：字面 / 尾 `/*` 严格一层 / 中段 `*` 恰好一段 / `**` 跨任意层）自 v0.1.20 起，
启动期对「尾 `/*`」条目打一条聚合 WARN，提示「改写为 `**`」。三个问题：

1. 尾 `/*` 是表达「严格一层」的**唯一**写法（尾段是动态段时只能用 `/*`），改 `**` 会扩面
   （`**` 含零层与任意深）→ 提示与事实矛盾；
2. 这类条目**永远无法消音**（没有任何配置键/标记能让它退出聚合）；
3. 提示**每次都打**，大型部署里会淹没真正要紧的启动 WARN。

## 2. 设计

### 2.1 判定：先订正适用面，再按真实影响面

**适用面＝只有 `auth.anonymous_paths`**（v0.1.23 订正）。依据见 §3.1。

对 auth 列表，**两个条件同时成立**才告警（`oj/src/app.rs`）：

| 条件 | 判据 | 实现 |
|---|---|---|
| ① 旧式前缀形态 | 只有尾段那一个 `*`、其余段全字面 | `is_legacy_prefix_shape`（裸后缀口径，对齐 v0.1.19） |
| ② 确实丢了面 | 存在已注册路由可达「head + ≥2 段」的路径 | `tail_entry_loses_coverage` → `view_reaches_beyond_one_layer` / `view_can_produce_at_least_two` |

- 条件① 的语义：旧 oj-auth 实现是 `strip_suffix("/*")` + `starts_with`（尾 `*` = 任意深度），
  只有「字面前缀 + 尾 `*`」这种形态当时能命中真实请求；含中段 `*` 的结构条目
  （`/public/anchor/*/issues/*`）当时**匹配不上任何请求**，只能诞生于 v0.1.20 的四形态语义。
- 条件② 的口径：旧语义覆盖 `head + ≥1 段`，收紧后只覆盖 `head + 恰好 1 段`，
  **丢掉的恰是 `head + ≥2 段`**；`**` 额外多出的**零层**（裸 head）旧语义同样没覆盖 → 不算丢面。
- 路由一侧用**段级视图**（`anon_view_of_route`：剥 base、`{param}`→`*`、`{*rest}`→`**`），
  而不是把两个模式送进 `server::path_matches` 对拍（后者在 catch-all / 带参路由上会漏报，见 §5.1-A2）。
- 调用点在**路由表建好之后**（`warn_legacy_tail_wildcards(&cfg, &route_views)`），因为条件②需要路由集。

### 2.2 逃生门：条目对象形态 `{ path, one_layer }`

`anonymous_paths` 元素类型 `String` → `AnonPath`（`src/config.rs`）：

```yaml
anonymous_paths:
  - /auth/login                                   # 字符串简写
  - { path: "/idp/*", one_layer: true }           # 对象形态：显式确认「有意一层」→ 永久退出 WARN
```

- **手写 `Deserialize`**（不用 `#[serde(untagged)]`）：只认 `path` 与 `one_layer` 两个键，
  未知键 / 缺 `path` / 类型错都给指名道姓的报错（untagged 会把 `one_layr: true` 静默吃成 `false`）。
- 消费侧统一归一为 `Vec<String>`（`config::anon_paths()`）：server 的 `Pipeline.tenant_anon` 与
  oj-auth 插件的 cfg JSON 都只吃字符串 → **插件零改动、ABI 保持 8**。
- 装配期 fail-fast（`config::validate_anon_paths()`）：`one_layer` 标在**末段不是 `*`** 的条目上
  直接报错（段级口径，与匹配层「忽略空段」一致）。

### 2.3 被否决的替代形态（架构评审背书）

| 替代 | 否决理由 |
|---|---|
| 全局开关（`warn: off`） | 粒度错：连真阳性一起消音 |
| 平行确认清单（`anonymous_paths_confirmed: []`） | 与条目分离、需按路径配对，必然漂移 |
| 只写文档、不给机制 | 等于没有逃生门（U39 的原始诉求就是「无手段消音」） |

对象形态把「确认」与「条目」**共址**，是正确粒度。

## 3. 证据与假设

### 3.1 两侧旧语义（实读 git 历史）

```
$ git show v0.1.19:server/src/lib.rs | sed -n '94,105p'      # tenant 侧（server::path_matches）
/// 精确匹配或尾 "/*" 严格一层前缀通配 …… 此处按测试收紧为严格一层。
pub fn path_matches(list: &[String], path: &str) -> bool {
    list.iter().any(|p| match p.strip_suffix("/*") {
        Some(prefix) => match path.strip_prefix(prefix) {
            Some(rest) => rest.starts_with('/') && !rest[1..].contains('/'),   // ← 已是严格一层
            None => false,
        },
        None => path == p,
    })
}

```

且 v0.1.19 的租户豁免（`git show v0.1.19:server/src/lib.rs` 的 `handle()`，`:364`）走的就是
`server::path_matches`。**结论：v0.1.20 的「任意深度 → 严格一层」收紧只发生在 auth 侧**；
v0.1.20 CHANGELOG 兼容性条目把两条列表并列，措辞不精确（已在 CHANGELOG 原文加 v0.1.23 订正注）。

### 3.2 「只看已注册路由」的充分性

`/blob` 下载分支与静态站点兜底都在 auth/tenant 前置管线**之前**直接 `return`，因此
`anonymous_paths` 对它们不产生效力 → 匿名条目的实际影响面 = 已注册路由集。
`server/src/lib.rs` 该分支处已加**互指注释**（改动提前返回顺序、或让它们咨询匿名表时必须同步本判定）。

## 4. 行为变更与兼容性

- 启动日志：迁移 WARN **只针对 auth**（tenant 不再参与）；两个条件同时成立才打。
- 配置面：`anonymous_paths` 新增对象形态（旧字符串写法解析结果逐字节不变，`config::anon_paths()`
  产出的 `Vec<String>` 与改动前一致；插件侧零改动、ABI 8 不变）。
- 新增 fail-fast：`one_layer` 标在末段非 `*` 的条目上报错。
- `oj build`：读配置失败由**静默回落**改为打 warn（`sql_guard` 静默 off 会让 CI 的 tenant 声明校验失效）。

## 5. 评审意见与处置

### 5.1 已采纳

| # | 评审意见（来源） | 处置 |
|---|---|---|
| A1 | **WARN 前提对 `tenant.anonymous_paths` 是伪前提**：v0.1.20 收紧只在 oj-auth 侧（架构 P1） | 采纳方案 a：**迁移 WARN 只对 auth 列表生效**（`migration_warn_entries`）；CHANGELOG v0.1.20 条目加订正注；`tenant-guide` / `api-manual` / `02-config` / `scenarios` / `SKILL` 全部限定到 auth。理由：保持双列表就得为 tenant 编一套「没有迁移」的文案，噪音（U39 的核心痛点）也不减；tenant 的「你可能想要 `**`」价值由四形态文档承担 |
| A2 | **条件② 用「模式对拍模式」会漏报**：路由视图含 `*`/`**`，`path_matches` 把 path 侧的 `**` 当普通段（开发 P1-1 / 架构 P2） | 采纳：改为**段级**判定（`view_reaches_beyond_one_layer`：逐段消费 head，`**` 回溯吃 0..n 段，再要求剩余视图能产出 ≥2 段）。反例 `/file/*` × 路由 `/file/{*path}`、`/zzz/*` × 路由 `/v1/api/{x}/detail/sub` 已写成单测 |
| A3 | **「仅差零层」被算作会多命中 → 残留噪音**（开发 P2-1） | 采纳：条件② 要求「head + ≥2 段」；`/user/account` + 条目 `/user/account/*` 不再告警（旧语义也没覆盖裸根，无丢面） |
| A4 | **`validate` 用裸后缀与匹配层「忽略空段」不一致**（开发 P2-2） | 采纳：校验改**段级**（末段 == `*`），`/idp/*/` 合法；WARN 侧保持裸后缀（对齐 v0.1.19 `strip_suffix`）并在注释写明这是**有意差异** |
| A5 | **untagged 的 `one_layr` 笔误静默失配**，与「不让配置撒谎」相悖（开发 P2-4 / 架构 P2） | 采纳：手写 `Deserialize`（map visitor），未知键 / 缺 `path` / 类型错都报错并给出合法形态；补 1 条用例 |
| A6 | **untagged 报错只给 "did not match any variant" 且指向列表首元素**（开发 P2-3） | 采纳（含位置）：手写 visitor 后不仅文案指名到键，**位置精度也一并修好**——实测出错条目在第 7 行时报 `tenant.anonymous_paths[3]: … 收到未知键 \`one_layr\` … at line 7 column 7`（评审测得的 untagged 行为是指向列表首元素 `line 4`） |
| A7 | **`oj build` 静默吞配置解析失败 → CI 门禁静默失效**（开发 P2-5 / 架构 P2） | 采纳（轻量版）：`sql_guard_of_config` / `tasks_dir_of` 解析失败改为打 warn（含后果说明）。**未采纳**「把 `validate_anon_paths` 下移到 build/migrate」——见 5.2 |
| A8 | **聚合用例复刻了实现，钉不住被测函数**（开发 P2-6） | 采纳：抽出 `legacy_entries` / `migration_warn_entries` 纯函数，`warn_*` 只负责打印；用例直接打这两个函数 |
| A9 | 文档行号漂移（开发 P2-7） | 采纳：`02-config.md` 的校验表改为按函数名引用，不再写死行号 |
| A10 | **静态/blob 绕过匿名匹配这一假设只有注释、无可测耦合点**（架构 P2） | 部分采纳：按本仓既有「两处实现互指注释」的做法，在 `server/src/lib.rs` 的 blob/静态分支写明该耦合与同步义务；**未采纳**再加 server 级测试（见 5.2） |
| A11 | **OIDC 推荐面（`/idp/**`）与 sample 面（`/idp/* + one_layer`）两种叙事未互指**（架构 P2） | 采纳：`oidc-integration.md` 补「两者等价、sample 更窄」的互指；`§8` 清单措辞对齐；`sample/README.md` 同步 |

### 5.2 未采纳（附理由）

| # | 意见 | 不采纳理由 |
|---|---|---|
| R1 | 把 `validate_anon_paths` 提到 `load_app_config` / 让 `oj build` 也 fail-fast（架构 P2 / 开发 P2-5 的强版本） | `oj build` 的既有契约是**允许配置缺失或不参与装配**（`config.yaml` 不存在也要能 build，见 `build_cmd.rs` 注释）；`oj migrate`/`fixture`/`schema diff` 走「瘦身装配」且不使用 `anonymous_paths`，为它们加与自身无关的硬校验会破坏该契约。处置：build 侧只出声（A7），并在 `02-config` §4 点明「fail-fast 只发生在 server/test 装配」 |
| R2 | 加 server 级测试断言「静态托管与 `/blob` 的结果与 `anonymous_paths` 无关」（架构 P2） | 需要构造 app 夹具，且断言的是「某条路径不经过某条管线」这种否定式事实——用互指注释（A10）表达同步义务更便宜、更不易腐坏 |
| R3 | `/health` 与 `{base}/plugins` 是 axum 层保留路由、不在 `route.listing()` 里；若业务恰有同名路由，WARN 可能**多报**（架构 P2 第二条假设） | 影响仅「多打一条提示」，且该路由本来就被保留路径遮蔽（不可达是既有事实）。登记为已知边界（§7），不为它引入「可达路由」这一新概念 |
| R4 | 条件② 遇到 catch-all 路由一律按「可能更深」多报以求 sound（架构 P2 的建议备选） | A2 的段级判定已能正确处理 catch-all（`**` 能产出 ≥2 段），无需退化成保守多报 |

### 5.3 评审明确背书、本版未改动

1. 条件① 的**形态判据**本身（`is_legacy_prefix_shape`）；
2. `one_layer` 只做告警开关、**不改变匹配语义**（严格一层语义仍单一来源于 `server::path_matches`）；
3. `validate_anon_paths` 这道 fail-fast 门的存在；
4. WARN 只看已注册路由 + 调用点后移到建表之后；
5. 归一化在**消费边界**做（`config::anon_paths()`），插件与 ABI 零改动；
6. `tenant.` 段同样接受对象形态（那里标记＝备注）；
7. `oj/tests/sample_config.rs` 这类「发行样例可解析 + 过校验」的回归钉子；
8. `sample/global.d.ts` 无需改动（它描述运行期全局，不含配置类型）。

## 7. 已知边界与残留

1. **保留路由遮蔽导致的多报**：业务路由与 `/health` / `{base}/plugins` 同名时，`table.listing()`
   仍会计入后者（R3，未修）。
2. **`oj build` / `oj migrate` 不做条目形态的硬校验**：口径与 server/test 不同（有意的，见 R1）；
   `02-config` §4 已写明。
3. 影响面判定的**前提**（静态/blob 不经匿名匹配）以互指注释维护（A10），不是编译期约束。
4. 条件② 的判定是「存在更深已注册路由」的**存在量化**，不区分该路由当前是否可达（保留路由
   遮蔽、`replaced` 路由等情形）——宽进（可能多报）优于漏报，符合迁移提示的用途。
