## 4. v0.1.20 平台侧交付设计

### 4.1 A1 · 匿名访问双层（U2，P0 阻塞级）

**现状链路**：`server/src/lib.rs:362-376`（租户头提取 → `path_matches` 豁免 → `tenant_id=None`）→ `ReqState.req.tenant_id` → 构造器侧 `query.rs:1529-1545 apply_tenant_guard`（tid=None → `:829-830` 拒绝）与裸 SQL 侧 `guard.rs:437-439`（tid=None → 拒）。

**第一层：通配语义升级**

统一为一套段匹配（`match_path(pattern, path)`，纯函数）：

| 模式        | 语义                          | 例                                                  |
| ----------- | ----------------------------- | --------------------------------------------------- |
| 字面        | 逐段全等                      | `/health`                                           |
| 尾 `/*`     | **严格一层**（维持现状，不放宽） | `/public/anchor/*` → 命中 `/public/anchor/z`，不命中 `…/z/states` |
| 中段 `*`    | **新增**：匹配任意单段        | `/public/anchor/*/states`                           |
| `**`        | **新增**：跨段（≥0 段）       | `/public/**` → 命中任意深度                          |

- **尾 `*` 保持一层**是安全决定：既有配置依赖该语义（POC #5、`docs/oidc-integration.md:79`），放宽等于静默扩大免租户/免鉴权面；需要深度请用 `**`。
- 两处持有（`server/src/lib.rs` 与 `plugins/oj-auth/src/lib.rs`，插件不可依赖 server，沿用现有注释互指做法），**语义与单测矩阵必须同步**；oj-auth 侧由「尾 `*` 任意深度」收紧为一致语义（§7 行为变更 + 迁移提示：改用 `/x/**`）。
- 新增单测：下游实测五形态（字面 / 尾一层 / 中段 `*` / 单模式多 `*` / `**`）逐条钉死。

**第二层：匿名租户上下文 —— `db.asTenant(id)`**

候选与取舍：

| 候选                                | 评估                                                                                                 | 结论       |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------- |
| **`db.asTenant(id)`（请求级显式）** | 与既有 `db.asSystem()`（`db.rs:281-287`，`bootstrap.js:390,405`）同构：请求级、reset 即失效、审计日志 | **选此**   |
| 按 host/域名解析租户                | 需 slug→uuid，正是 U20（下游域，F7 已记 v2 留痕）；平台侧无租户目录可查                              | v2 留痕    |
| 匿名全租户查询原语                  | 等价于放开跨租户读，与多租户防护目标直接冲突                                                          | 否决       |

语义（评审后收紧）：

1. **显式匿名标志**：`RequestInfo` 增 `anonymous: bool`（`src/bridge/http.rs:23-40`），**仅** `server/src/lib.rs` 的豁免分支（`None if exempt`，:374）置 true；租户未启用（:380）、WS 帧（`frame_pool.rs:319`）、任务桥（`mod.rs:419`）、`oj test` 默认路径**一律 false**。判据是 `anonymous && tenant_id.is_none()` —— 用 `tid.is_none()` 判会误放行 WS/任务/测试路径。
2. **fail-closed 开关**：`tenant.allow_as_tenant: bool`（**默认 false**，与 asSystem 不同——asTenant 面向公开面且 id 无从校验）。未开启时调用直接 Err。
3. 调用后等价于把 `tenant_id` 注入本请求（写 `req.tenant_id`），**防护机制不变**：构造器侧 `apply_tenant` 照常注入 `tenant_id` 条件，裸 SQL 侧 deny 仍要求「mentions + param_has」（`guard.rs:437-439` 的 `Some(_)` 分支）。但**身份本身不可信**——安全性取决于 id 的派生链（评审意见 4，§8 已改述为「授信 handler」）。
4. 与 `asSystem` 的区别写进文档：**asSystem = 完全绕过租户防护（跨租户裸奔，仅系统任务，无开关）；asTenant = 仍强制租户条件，只是身份由 handler 显式声明，且需显式开关**。
5. 审计日志：`db.asTenant(...) invoked (anonymous request, tenant=…)`（`eprintln!`，与 asSystem 同款）。
6. **红线（写进 api-manual）**：`id` 必须是服务端从可信锚点（anchor → workspace uuid 查表）派生的值，**绝不可取自请求参数**；`ReqState::reset` 后失效（请求级）。
7. 测试态授信：`oj test --anonymous` 让测试请求带 `anonymous = true`（`test_ext.rs:69` 的 `RequestInfo::default()` 否则恒 false，公开面 handler 无法测）。

**验收**

```bash
# 1) 多层通配豁免（不再 400 missing tenant header）
curl -i -H 'Accept: application/json' http://127.0.0.1:9778/v1/api/public/anchor/v1c/states/
# 2) 匿名请求 + asTenant 派生租户 → 200（不再 500 require tenant context）
curl -s http://127.0.0.1:9778/v1/api/public/anchor/v1c/states/ | head -c 200
```

### 4.2 A2 · 静态托管：SPA 深链接回落 + 路由感知 meta 注入（U1）

**现状**：`server/src/lib.rs:438-445` 静态兜底 → `:478-496 resolve_static` 逐段解析、目录→`index.html`、**未命中即 404**。生产无模板、无注入点（与下游 `static-handler.ts` 的 dev-only 注入同源）。

**(a) SPA 回落**

- 触发条件（五条全满足）：`GET|HEAD` + `resolve_static` 未命中 + 请求路径**无扩展名** + `Accept` 视为 html + **不以 `api_prefix` 开头**（评审意见 6：否则 `app_prefix="/"` 时拼错的 API 路径会返回 200 index.html 吞掉 404）→ 服务 `<root>/index.html`。
- 回落目标**固定为 `root/index.html`**，不接受任何来自 URI 的段（复用 `resolve_static` 的解码/越界守卫，不新增穿越面）。
- 新配置 `server.app_spa_fallback: bool`，**默认 false**（现状保持）：静默把 404 变 200 会掩盖真实错配；SPA 工程显式开启，文档推荐 SPA 打开。
- `Accept` 口径（评审意见 13）：**缺失 / `*/*` / 含 `text/html`（q>0）**均视为 html（curl 默认 `*/*`，否则验收命令都不生效）。

**(b) 路由感知 meta 注入（廉价中间态，非 SSR）**

- 新配置 `server.html_meta: Option<String>`（相对静态根的子目录名，如 `"__meta"`）；为 `None` 时零开销（现状）。
- 送出**任何 HTML**（含 `/` 与目录解析出的 `index.html`、以及 `.html` 文件——否则首页无 title，与需求矛盾，评审意见 12）前，按请求路径查 `<root>/<html_meta>/<sanitized-path>.json`（键白名单：`title`、`description`、`og:*`、`twitter:*`），命中则**只注入 `<title>` 与 `<meta>`/`<link rel=canonical>` 标签**（不注入任何脚本，规避 CSP nonce 问题），值一律 HTML 转义。
- 该目录**不对静态服务公开**：`resolve_static` 对 `html_meta` 目录名返回 None（评审意见 7）。
- **不做缓存**（一次 stat/read，避免 `AppState` 是 `Clone` + `Send` 前提下的锁与无界增长）；大流量场景前置 CDN。
- 产物由构建期/离线生成（prerender 或脚本），**平台不引入 SSR 运行时**。这正好覆盖下游 `space.public.anchor-seo-meta`（服务端 per-route title/OG）的 blocked 诉求。

**验收**

```bash
curl -s -H 'Accept: text/html' http://127.0.0.1:9778/space/issues/abc | grep -i '<title>\|og:title'
# → 200（不再是 404），title 为 __meta/space/issues/abc.json 注入值
```

### 4.3 A3 · `oj test` 默认库重定向（U33）

**现状**：`oj/src/test_cmd.rs` 复用 `App`（`app.rs:471 connect_dbs(&cfg.db, …)`），字面 `default` 由 `guard.rs:458-476 bound_db` 解析到 `db.default` —— 测试写在开发库上（下游实证：读到了 `poc` 库 1000 行非种子数据）。

**设计（评审后改为装配期重定向）**

- `App::from_config` 收 `db_override: Option<String>`，**先算出 `db_key`（override 或 `"default"`）再装配**：`migrate.apply_all` / `verify_all`（`app.rs:480-481`）、`build_schema_and_modules`（`:493`）、`seed.replay_all`（`:497`）、`load_fixtures`（`:501`）四处**全部跟随 `db_key`** —— 只改运行期 `bound_db` 会让 test 库无表无种子，比现状更糟（评审意见 2）。
- 运行期 `StableState.db_override`（经 `Extras` 注入，`mod.rs:552` / `:1644` / `app.rs:734` 三处同步）+ `bound_db` 解析顺序：**显式 `DB("name")` → manifest `db:` 绑定 → `db_override` → `default`**。
- `oj test`：`db.test` 存在 ⇒ override `"test"`；新增 `--db <name>`（不存在即 fail-fast），启动日志打印实际库名；`db.test` 不存在且未指定 ⇒ 醒目 WARN 后继续 `default`（不静默）。
- 新增 `--anonymous`（评审意见 10），配合 §4.1 的测试态授信。
- 新增 e2e：`oj test` 期间一次写入落在 `db.test` 的 sqlite 文件（而非 `db.default`）。

> 属**行为变更**（默认库变了），CHANGELOG 须单列；理由优先级：写坏开发库是真实事故 > 保持默认。

### 4.4 A4 · 构造器 LIMIT 可配置 + 截断可观测（U30）

**现状**：`query.rs:371-372` `LIMIT_DEFAULT=100` / `LIMIT_MAX=1000`；`:1360-1367` 显式 limit clamp 到 MAX、隐式 DEFAULT 只给顶层。截断**无任何信号**（下游“静默少数据”痛点在此）。

**设计**

- 新配置段 `db_query:`（评审意见 8 改名；**不能放 `db:` 内**——`Config.db` 是 `HashMap<String,String>` 的 name→DSN，`config.rs:470-473`）：

  ```yaml
  db_query:
    default_limit: 1000   # 隐式 LIMIT（默认 100；校验 1 ≤ default_limit ≤ max_limit ≤ 100000）
    max_limit: 10000      # 显式 limit 的 clamp 上界（默认 1000；硬顶 100000 防 DoS）
  ```

  装配期校验失败即 fail-fast（`0` 与 `default_limit > max_limit` 均非法）；字段名即键名，
  结构体 `deny_unknown_fields` —— 拼错的键（如 `default`）在启动期报错，不静默取默认值。
- **不穿透 `build_statement` 递归签名**（评审意见 17）：在 op 层 `normalize_limit(&state, &mut req)` 归一化——顶层 `limit=None` → 填 `default_limit`；显式 → `min(limit, max_limit)`。保留「嵌套子查询不隐式截断」的既有语义（`query.rs:1360-1365`）。
- **截断信号**：`applied = min(显式或默认, max_limit)`，**`rows.len() >= applied` 即写头**（含「显式 limit 被 clamp」这类静默截断，评审意见 9）。头经 `ReqState.headers` → `Capture.headers` → `capture_response`（`server/src/lib.rs:543-550`）写出，**仅 `json.*` 路径生效**；blob/静态走 `file_response`，不冲突。
- **不改信封形状**（`{code,msg,data}` 契约不动），避免破坏下游 12 个生成 client。
- 下游另一半诉求（`archived` 参数、`group_by`）是 handler 业务面 ⇒ 归 D 类，指引：客户端分流或自建端点（§6）。

### 4.5 A5 · 支持项（不进代码）

- **U24（test email）**：平台**已具备**——v0.1.19 mail 轴。下游 `instance/email-credentials-check` 改走 `mail.sendSync`（同步 transport，worker 内 `spawn_blocking`）即可真实外呼；注意两点：① 收件人须落在该 profile 的 `allowed_recipients` 白名单（否则 `{code:5}`）；② 未配置 `smtp:` 段时 `mail.*` 抛错，handler 需按“SMTP 未配置”分支回 400。附 sample 片段于 api-manual §6。

## 8. 风险与不做清单（v0.1.20）

- `asTenant` 的越权面：**防护机制不变，但身份不可信**——平台无从校验 id 是否为真实租户（评审意见 4），它校验的只是「SQL 是否带 tenant_id 条件且绑定该值」。安全性完全取决于 id 的派生链（anchor → 查表 → uuid），故定位是**授信 handler**：默认关闭（`tenant.allow_as_tenant`）＋ 仅匿名请求可用 ＋ 审计日志 ＋ 文档红线四道。不额外做租户目录校验（无数据可查）。
- 静态 meta 注入：只注入 title/meta/link 且 HTML 转义；不注入脚本（CSP nonce 不可得）。
- **明确不做**：SSR/prerender 运行时（U1 方案 2）；域名路由 slug→uuid（U20）；vendored 后端任何端点（D 类）；`@plane/*` 包改动；CI 平台建设（U36，本版只出方案）；共享资产/模块产物压缩与门禁（oj-module 侧 U14/U15）。
