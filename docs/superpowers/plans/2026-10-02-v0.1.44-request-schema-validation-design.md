# v0.1.44 入参校验设计 —— PR-6 4b

> Stage 4 后半：`schema` 注册表 + `run_module` 入参校验 400 + `server.schema_validation` 开关。
> 前置：4a（`oj openapi` 生成 + `--check` 漂移，v0.1.43）已落地。

## 1. 目标与非目标

**目标**

- handler 可**声明**入参契约（新 surface：导出函数的 `.schema`，与既有 `.route` 同构）。
- 声明即为执行时校验依据：违反 → HTTP **400**（信封 `{"code":400,"msg":...}`）。
- `server.schema_validation` 开关控制是否启用。
- 同一份声明顺带喂给 `oj openapi`，补齐 4a 留白的 `parameters` / `requestBody`。

**非目标（明确留白，后续步）**

- 响应 schema 校验（只校验入参）。
- multipart `http.files` 内容校验。
- `$ref` / `oneOf` / `format` 等完整 JSON Schema 语义（见 §4 受支持子集与 fail-fast）。

## 2. 声明形态（JS 侧）

与 `.route` 完全同构：交割导出的函数对象上挂 `.schema`。三个通道分开描述，
对应 `RequestInfo` 的 `params` / `query` / `body`：

```js
export default { post, get };

get.schema = {
  params: { type: "object", required: ["id"], properties: { id: { type: "integer" } } },
};

post.schema = {
  query:  { type: "object", properties: { page: { type: "integer", minimum: 1 } } },
  body:   { type: "object", required: ["name"],
            properties: { name: { type: "string", maxLength: 20 },
                          tags: { type: "array", items: { type: "string" } } } },
};
```

**为什么不分 failsafe 到单个 body schema**：`params`（路径段）/`query`/`body` 三者的
来源、类型约束、以及是否需要字符串→数字强转各不相同；合并成一个 JSON Schema 会迫使
用户用 `type: string` 描述明明是数字的路径参数。分通道同时天然映射到 OpenAPI 的
`parameters(in:path)` / `parameters(in:query)` / `requestBody`。

## 3. 数据流

```
            ┌── dev: 内省（Bridge::introspect_decls）      ┐
handler .schema ───────────────────────────────────────────┐
            └─ release: oj build 落 dist/*/routes.js       │
                        （每 entry 增可选 schema 字段）      │
                                                            ▼
                                              ValidationRegistry（键 = (api 文件绝对路径, js 方法名)）
                                                            │ 经 Extras → StableState → run_module
                                                            ▼
                                      请求入参校验 → 违反则 json.fail(400, msg)
```

### 3.1 键的设计：`(file_path, method)`

`Lookup::Hit` 已把命中解析为 `file: PathBuf`，正是 `run_module(api_path, method, ..)` 的入参，
也是 4a 生成物里 `x-oj-file` 的取值 —— **三处天然对齐**，且不需要把 route pattern 带到查询期
（`lookup` 目前不返回 pattern，改 `Lookup` 要动全部 ~30 处测试匹配）。故键采用
`(绝对路径, "get")`，不再引入 pattern。

### 3.2 单次内省同时取 route + schema

`RouteTable::build` 的内省闭包签名是 `Fn(&Path) -> Result<Vec<(String, Option<String>)>, String>`
（无 Send/Sync 约束，且当前实现是顺序调用）。新增 `Bridge::introspect_decls`，一次返回
`{"get": {"route": "..."|null, "schema": {...}|null}}`；消费方用一个携带 `RefCell<Vec<_>>`
的闭包在一次遍历里同时产出路由行与 schema 表，**不重复起 Bridge/线程**（dev 内省每文件起线程，
翻倍开销不可接受）。

- `src/bridge/mod.rs`：新增 `introspect_decls`（**不改动**既有 `introspect_module`，
  保持 `decls_from_value` 契约零影响）。
- `server/src/routes.rs`：新增 `decls_with_schemas_from_value` 解析器。

### 3.3 release 侧：扩展 `routes.js`

现有每行 `{ method, pattern, file }`；增**可选** `schema` 字段。旧构件（无该字段）解析为
`None` → 向后兼容，`entries_from_value` 用 `.get("schema")` 取、缺失即 None。
`RouteEntry` 增 `schema: Option<serde_json::Value>`。

## 4. 校验器：手搓最小子集，**不新增依赖**

调研结论：仓库当前**无任何 JSON Schema crate**（`jsonschema`/`valico`/`serde_valid` 全无），
且 4a 已确立「手搓 OpenAPI 3.1、避免额外 crate」的先例。`docs` 与多处注释把
「依赖树新增节点」当作需论证的成本。故自研**最小 OpenAPI-flavored 子集**：

受支持：`type`（含类型数组 / `nullable`）、`required`、`properties`、`items`、
`minimum/maximum`、`minLength/maxLength`、`pattern`、`enum`、`additionalProperties`、
`minItems/maxItems`、`properties` 递归嵌套。

**红线（安全相关，最关键）**：遇到**不在白名单**内的关键字（如 `$ref`、`oneOf`、
`not`、`patternProperties`、`format`、`dependencies`…）一律
**注册期 fail-fast**（启动/构建期报错），**绝不静默跳过**。
这是本设计的防护核心 —— 静默放行 = 「插旗式声明」漏洞。
同时：schema 本身非法（非 object、未知 `type` 字面值）也 fail-fast。

**类型强转**：`params` / `query` 通道在类型目标为 number/integer/boolean 时，
对**字符串**源值做明确强转（URL 里没有类型概念），失败即违反。这是必须显式处理的语义。
`body` 通道（已是真 JSON）**不做**字符串强转。

## 5. 运行时接入点

在 bridge 的 `run_module` 内、调用 handler **之前**校验 —— 与既有
「方法未导出 → `json.fail(405)`」同处同一位置、同一手法
（写 `envelope::fail(400, msg)` 进 `ReqState` → Capture 带 400 → `capture_response` 原样回写）。

**为什么放 bridge 而不是 server 的 `run_route`**：

- plan 原文即 `run_module 入参校验`；
- 防御纵深切得更深 —— 覆盖 `run_module` 的**全部**调用方
  （HTTP 路径 + `dispatch_meta_handler` 内部派发），而非只有外部 HTTP 路径；
- 注入成本已被既有设计吸收：`Extras` 是 `#[derive(Default)]`，加一个
  `Option<Arc<ValidationRegistry>>` 字段对全部既有 `Extras::default()` 调用点透明。

## 6. 配置开关

`src/config.rs` → `ServerCfg` 增：

```rust
/// 入参校验开关（v0.1.44）：true = 按 handler 声明的 .schema 校验 params/query/body，
/// 违反 → 400。**默认 true（fail-closed）** —— 声明而不执行 = 假契约；
/// 当前无人声明 .schema，故升级无行为变化。
#[serde(default = "default_true")]
pub schema_validation: bool,
```

+ `Default for ServerCfg` 同步字段；经 `oj/src/app.rs` 装配 → `Extras.validation`。
`default_true()` 已在 `oj/src/schema.rs:113` 存在，直接复用（DRY）。

放开擞待评审确认的一点：**默认 true vs false**。倾向 true：这是「守卫」而非「功能」，
项目既有守卫哲学（chmod 记忆：`静默降级是坑`）倾向 fail-closed；且当前无存量
`.schema`，默认 true 不会改变任何现有行为。

## 7. 测试（击穿优先）

- **校验器单元**：类型不符 / required 缺失 / additionalProperties / 嵌套 array+object /
  enum / minLength / pattern / 数值边界；
- **防护击穿（重点）**：
  - 未知关键字 `$ref` / `oneOf` 必须 fail-fast，**不得静默放行**（写 dead-fixture 钉死）；
  - 键错配（错误 file 或 method）→ 不得误拦；
  - 开关关闭时即便违反 schema 也**不得**返回 400；
  - 字符串→数字强转：`?id=abc` 必须拒；`?id=12` 必须过。
- **集成/e2e**：真 HTTP 违反 → 400 信封；合规 → 放行；`schema_validation: false` → 不校验。
- **4a 兼容**：旧 `routes.js`（无 schema 字段）仍可加载。
