# v0.1.108 `db.explain` 实施计划（G3 执行计划归一）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `db.explain(sql, params?, opts?)`，PG / MySQL 返回跨方言归一的 plan 节点树（含 category），sqlite 报结构化 `OJ_DB_UNSUPPORTED`。

**Architecture:** 新模块 `src/bridge/db_explain.rs` 只含三样：方言 EXPLAIN 前缀常量、PG/MySQL JSON→PlanNode 归一纯函数、`op_db_explain` 壳。壳 = 内层 SQL 过一遍 `check_tenant_raw` → 拼前缀 → **直接调 `db_query::query_impl` 原函数**（守卫/配额/trace/session 零复制），首行首列取 JSON → 归一。bootstrap.js 挂 `db.explain`。

**Tech Stack:** Rust + deno_core op2 + serde_json；测试走 `cargo test --release`（禁 debug）；真库腿 env-gated（`OJ_TEST_PG` / `OJ_TEST_MYSQL`）。

**Spec:** `docs/superpowers/specs/2026-10-29-dbx-upstream-g3-u14-design.md`（§v0.1.108 及「已定裁决」节；本文档与其冲突时以 spec 为准）

## Global Constraints

- 禁 debug 构建/测试：一律 `cargo test --release`、`cargo clippy --release --workspace --all-targets -- -D warnings`。
- cargo test 接管道必须 `set -o pipefail`；**不可并发两个 cargo test**。
- 异步测试一律 `#[tokio::test(flavor = "current_thread")]`（JsRuntime 是 `!Send`）。
- `bootstrap.js` 必须保持 7-bit ASCII。
- 方言前缀是宿主常量，用户只供内层 SQL；**绝不内联参数值**（红线）。
- 多语句输入（`SELECT 1; DROP ...`）由 `classify` 取最严风险级兜底——不在本模块特判。
- commit message 结尾 `unix@vip.qq.com ai`；版本号只改 `oj/Cargo.toml`（根 Cargo.toml 不动）。

## Review Focus

1. **多语句注入**：`db.explain("SELECT 1; DROP TABLE t")` 在 read_only 别名上——期望：被 `check_access` 按最严级拒（EXPLAIN 前缀不改变 classify 取最严的语义）。钉在 Task 4。
2. **未知方言名**：插件描述符声明名是开放契约（可能是 mysql/postgres/sqlite 之外的任意串）——期望：结构化 `OJ_DB_UNSUPPORTED`（capability=`explain`），不 panic 不回落。钉在 Task 4。
3. **结果取列按位置不按名**：PG 列名 `QUERY PLAN`、MySQL 列名 `EXPLAIN`，均有版本漂移风险——期望：取首行首列值，不查列名。钉在 Task 2/3 的输入形态（从「首行首列字符串」喂入）。
4. **MySQL 带参 EXPLAIN 的方言兼容性**：sqlx 恒走 COM_STMT_PREPARE；带参失败是**已知可能**——期望：真机实验裁决（Task 1），失败则 params 非空 × MySQL 结构化报错（预写回落，Task 4 条件步）。
5. **Deny 模式租户 fail-closed**：`EXPLAIN UPDATE <未注册表>` 首词分派会绕过 guard 的 DML fail-closed 分支——期望：内层 SQL 单独过 `check_tenant_raw` 后被拒。钉在 Task 4。

```rust
/// G3 契约裁决实验（v0.1.108）：PG / MySQL 的 EXPLAIN 是否接受绑定参数在被解释语句内。
/// 结论写入 commit message：mysql 腿失败 → op_db_explain 需加 params×mysql 结构化报错。
#[tokio::test(flavor = "current_thread")]
async fn explain_accepts_bind_params_real_pg_mysql() {
    for (env, tag, sql) in [
        ("OJ_TEST_PG", "pg",
         "EXPLAIN (FORMAT JSON) SELECT 1 WHERE 1 = ?"),
        ("OJ_TEST_MYSQL", "mysql",
         "EXPLAIN FORMAT=JSON SELECT 1 WHERE 1 = ?"),
    ] {
        let Ok(url) = std::env::var(env) else { continue };
        if url.is_empty() { continue }
        let db = crate::bridge::SqlxAccessor::arc(&url).await.unwrap();
        let r = db
            .query_with_params(sql, &[serde_json::json!(1)])
            .await;
        assert!(r.is_ok(), "{tag}: 带参 EXPLAIN 必须可用（否则启预写回落）: {:?}", r.err());
    }
    if std::env::var("OJ_TEST_PG").is_err() && std::env::var("OJ_TEST_MYSQL").is_err() {
        eprintln!("skip: OJ_TEST_PG / OJ_TEST_MYSQL unset");
    }
}
```

### Task 5: `op_db_explain` + 注册 + bootstrap 挂载

**Files:**
- Modify: `src/bridge/db_explain.rs`（op + 测试）
- Modify: `src/bridge/mod.rs`（op 注册表加 `db_explain::op_db_explain`，放在 `db_query::op_db_exec` 之后）

**Interfaces:**
- Consumes: `db_query::query_impl(state, name, sql, params, call_timeout_ms)`（pub(crate)，签名照 db_query.rs）；`query::lookup(&state, &name)`（照 op_db_dialect）；`guard::check_tenant_raw(&state, &sql, &params)`；`db_error::unsupported(dialect, capability)`；Task 2/3 的常量与归一函数
- Produces: `pub async fn op_db_explain(state: Rc<RefCell<OpState>>, #[string] name: String, #[string] sql: String, #[serde] params: Option<Vec<Value>>, #[serde] opts: Option<DbCallOpts>) -> Result<Value, JsErrorBox>`；JS 面 `db.explain(sql, params?, opts?: {timeoutMs})`

- [ ] **Step 1: 写失败测试（Rust 侧 sqlite/未知方言 + JS 侧行为）**

Rust 侧（`db_explain.rs` tests）：
- 用 `sqlite::memory:` DSN 建 `SqlxAccessor`，`Bridge::with_dbs_and_loader`（模式照 db_tests.rs 既有腿），JS 调 `db.explain("select 1")` → 断言 code != 0 且错误为 `OJ_DB_UNSUPPORTED`、`data.capability=="explain"`。
- **多语句**：read_only 别名上 `db.explain("select 1; drop table x")` → 被拒（守卫链生效）。

JS 侧 Deny 租户用例（镜像 `probe_stream_tenant_guard_deny_four_states` 的 guard 装配）：`EXPLAIN UPDATE <未注册表>` → 拒（内层租户检查生效）。

- [ ] **Step 2: 跑测试确认失败**

Run: `cargo test --release --lib bridge::db_explain`
Expected: FAIL（op 不存在 / JS 侧 `db.explain is not a function`）

- [ ] **Step 3: 实现 op**

op 体（~30 行）：
1. `let da = super::query::lookup(&state, &name)?;` 取 `da.dialect_info().name`
2. 方言分派：`postgres`→PG 前缀、`mysql`→MySQL 前缀、其他 → `return Err(to_js_err(Box::new(db_error::unsupported(&name_of_dialect, "explain"))))`
3. `super::guard::check_tenant_raw(&state, &sql, &params)?;`——**内层 SQL**，先于包前缀（Deny fail-closed 补偿，守卫注释里写明原因）
4. `let rows = super::db_query::query_impl(state, name, format!("{prefix}{sql}"), params.unwrap_or_default(), opts.and_then(|o| o.timeout_ms)).await?;`
5. 首行首列取值：`rows[0].as_object().and_then(|m| m.values().next())`；字符串则 `serde_json::from_str`，已是 Value 则直接用
6. PG → `normalize_pg_plan(&v["Plan"])`；MySQL → `normalize_mysql_plan(&v)`
7. `Ok(json!({ "plan": node }))`

**条件步（仅当 Task 1 实验 MySQL 腿失败）**：Step 3 第 4 步前加 `if dialect=="mysql" && !params.is_empty() { return Err(...unsupported 点名最低版本...) }`，并补一条单测。
