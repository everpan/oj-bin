## 1. 值得肯定的设计

- **依赖方向干净**：`only-js` 不依赖 `server`/`oj`，插件只依赖 `oj-plugin-ffi`；
  核心内部重构不会破坏插件 ABI。
- **按轴 dlsym（ABI 7）**：加轴只需动 `AXES` + `Registrations` + vtable 类型，
  插件零感知、零重编译；`probe_axes` 的 `unreachable!` 防两表失步。
- **失败路径有纪律**：失败的 `JsRuntime` 一律丢弃不归还；boot 失败/熔断前先补跑一轮
  event loop（有 SIGSEGV 前科）；`KillSwitch` 用 `IsolateHandle` 而非裸指针，
  线程只持 `Weak`，`Drop` 跳过 self-join（有回归测试）。
- **配置治理一致**：「块存在即启用」贯穿全局，`Option<T>` 的 `None` 就是不装能力；
  装配期 fail-fast 覆盖证书、JWT secret、blob 歧义、迁移门禁、标识符白名单。
- **测试夹具集中**：`server::test_support` 是全仓唯一的证书夹具，避免密钥对到处拷贝。
- **`oj test` 的零 TCP oneshot 派发**：对标 Go Fiber `app.Test`，是本项目最有价值的
  测试基础设施之一。
- 代码注释质量高：关键处写清「为什么」（如 xtask 必须用 `--workspace` 的原因、
  `RefCell` 借位不可跨 await、`grouped=false` 因 mysql DDL 隐式提交）。

## 2. P0 · CI 与产物

### P0-1 sample 的 L1/L2 测试不在 CI

`.github/workflows/{release,plugin-matrix}.yml` 只跑
`cargo test --workspace --release -- --skip infinite_loop` + `fmt` + `clippy`。
`sample/tests/`（L1）与 `sample/test/`（L2）**一个都没跑** —— 即
`docs/testing.md` 里定义的端到端契约层没有自动化守护。

建议：补一个 `sample-tests` job（[`modules/08-testing.md` §6](modules/08-testing.md) 有现成 YAML）。
注意 `oj test` 走 `App::from_config`，会过证书门禁与迁移门禁。

### P0-2 插件构建列表漏 `auth`

`plugin-matrix.yml:100`：

```bash
for p in es db-mysql db-postgres blob-s3 bus-kafka bus-rabbitmq kv-redis; do
```

而 `tools/xtask/src/main.rs:25` 的 `PLUGINS` 有 **8** 个（含 `auth`）。
结果：CI 上传的 `plugins-<triple>` 包里没有 `oj-auth`，sample 的鉴权守卫装配会
fail-fast。建议直接用 `cargo run --release -p xtask -- build`，或至少补上 `auth`
—— 更好的做法是让 CI 消费 xtask 的清单而不是硬编码一份副本（副本必然失步）。

### P0-3 `cargo test --release -- --skip infinite_loop` 是常驻跳过

两个 workflow 都跳过 `infinite_loop`（部分平台 SIGSEGV）。这掩盖了一类真实缺陷
（V8 `terminate_execution` 后的隔离性）。建议按平台条件跳过
（`if: matrix.os != '...'`）而不是全局跳过，并留一条 issue 跟踪。

## 3. P1 · 配置与一致性

### P1-1 默认端口 778 vs 9778

`src/config.rs:58` `port: 778`，而 `README.md:75`、`sample/config.yaml:3`、
`docs/devkit/api-manual.md` 全是 `9778`。省缺 `port` 的用户会静默落到 778。
建议改成 `9778` 并在测试里钉死。

### P1-2 clippy 门禁对核心库无效

两个 workflow 都跑 `cargo clippy --workspace --all-targets -- -D warnings`，
但 **`src/lib.rs:1` 是 `#![allow(clippy::all)]`** —— 根 crate（最大的一个）整体豁免。
后果：`RefCell` 借位跨 await、冗余 clone 这类问题在核心库里不会被 CI 发现，
只能靠注释（如 `runtime.rs:83-85`）与人工评审。

建议：把 crate 级 allow 收敛为**模块/项级**（`#[allow(clippy::specific_lint)]`
+ 理由），逐步清零；至少先放开 `clippy::all` 里安全度高的分组。

### P1-3 `sample/test/` 与 `sample/tests/`

名字只差一个 s，但运行器完全不同（`oj test` vs vitest），且**用例大量重复**
（`user.account` / `news` / `admin` 三个文件的正例在 L1 里都有一份同场景）。

建议：不合并目录（运行器互斥），但改名 + 统一入口 + 去重复。
详见 [`modules/08-testing.md` §3–§4](modules/08-testing.md)。
